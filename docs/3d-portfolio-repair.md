# 3D portfolio repair — 24 September 2026

The existing React, React Three Fiber and GSAP portfolio is retained. The nine sections, original scene objects, personal video files, document assets and existing editor remain in the repository.

1. **Readability.** The full-screen canvas and several differently stacked HTML sections competed for the same space. Desktop now reserves 44% for readable content and 56% for the scene. The camera frames the existing objects within that scene column. Text panels no longer rely on large blurred overlays. Navigation and native dialogs sit above the content.
2. **Lag causes.** Camera telemetry updated App state every rendered frame, scroll progress updated App continuously, hover changes recreated the scroll controller, and every exhibition stayed mounted. The renderer also used uncapped pixel density, many local lights, large shadow maps and unnecessary per-frame allocations.
3. **React updates.** Camera and scroll values now stay in references. Only a changed section or milestone updates page state. A production browser check using React's devtools hook recorded no additional page-root commits while the scene animated at rest.
4. **3D rendering.** The canvas is loaded separately from the HTML. Desktop pixel density is capped at 1.5; lighting is limited to ambient, hemisphere and one directional light. Only the early desktop study uses a 1024-pixel shadow map. Adjacent exhibitions overlap during transitions; distant exhibition components unmount. Frame deltas are capped, vectors are reused, the research line is memoized and disposed, and desktop particles are reduced to 12.
5. **Video.** The existing 1280×720 `hero-video-opt.mp4` is used with the existing poster. The original video files are unchanged. Playback is muted, inline and looping, with a visible pause/play control. It pauses offscreen or in a hidden tab. Missing media and blocked autoplay retain a poster.
6. **Mobile and lower-power devices.** Phones use a compact opening scene, pixel density 1, no shadows or particles, and no video download. Rendering stops when the phone's opening scene is covered by the content. Save-Data and devices reporting four or fewer logical processors use a static, demand-rendered scene. Reduced motion removes camera travel, parallax and continuous animation while retaining section views and all HTML content.
7. **Accessibility.** The page has one main landmark, a skip link, a mobile menu, visible keyboard focus and ordinary pressed-state filter buttons. All five viewer entry points use native modal dialogs with focus containment, Escape and opener-focus restoration. Missing previews have readable alternatives. WebGL failure or context loss leaves the HTML portfolio usable.
8. **Deployment.** Vite uses `/E-portfolio/`. The entry explicitly imports `App.tsx`, avoiding its Windows filename collision with the legacy `app.js`. The repaired lockfile supports `npm ci`. Official Pages actions build on Node 22 and upload only `dist`; legacy routes, their scripts, the editor and evidence files are copied into that output without running the old generator over the React entry. The workflow tests the production build before deployment.
9. **Lint.** `npm run lint` passes (`tsc --noEmit`).
10. **Build and tests.** A clean `npm ci`, `npm run build`, 38 unit tests and 70 production-browser checks pass locally. Browser checks cover all nine sections, 1440/1024/768/390-pixel layouts, pixel-density caps, documents, all viewers, keyboard focus, reduced motion, Save-Data, missing video/images, unavailable Supabase, legacy records, autoplay refusal and WebGL failure/loss. They use Chrome with software WebGL; they are not a physical-device frame-rate measurement.
11. **Pages configuration.** This repair supplies `.github/workflows/pages.yml` with the required Pages and identity-token permissions, a `github-pages` environment and the `dist` artifact. Repository Settings → Pages must use **GitHub Actions**. Before the repair, branch publishing served raw `src/main.tsx` and the live React root remained empty. The PR/deployment record establishes the final publishing status.
12. **Remaining limits.** The separately loaded 3D bundle remains about 296 KB gzip and produces Vite's 500 KB uncompressed chunk warning. Actual frame rates on physical phones and Safari have not been measured. The existing rich teaching/gallery records remain in their repository data modules; this repair restores shared Supabase profile/about/qualification reads and preserves the existing editor and its legacy published pages, without changing the database schema or rewriting those records.

Supabase records are merged with safe defaults and validated before use; a failed request keeps the bundled content. The About section's conflicting institution and study dates were replaced with the already established shared education records. CTET remains applied, with the examination expected on 12–13 December 2026, and the observation dates remain 24–28 November 2025.

Browser-check screenshots and the machine-readable results are written to `outputs/production-checks/` and uploaded by the review workflow. To repeat locally, run `npm ci`, `npm run lint`, `npm test`, `npm run build`, then `npm run test:browser`. Set `CHROME_PATH` to an installed Chrome executable for the MP4 playback checks. CI uses the Chrome already provided by the Ubuntu runner.
