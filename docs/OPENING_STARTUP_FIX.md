# Opening before the first homepage paint

The original static homepage could paint before the deferred application downloaded and created the iris overlay. A delayed-app regression reproduced the exposed homepage followed by a late opening.

Home loads the self-contained classic `src/opening-entry.js` in the document head before its stylesheet. The build generates it from the startup guard, the same iris implementation used by module tests, and its entry lifecycle. Eligible first visits receive a temporary paper cover using the existing iris background. The opening claims that cover and removes it only after attaching the actual iris, within the same JavaScript task. No frame is intentionally left uncovered between those states.

Each newly loaded Home document plays the opening, including an ordinary reload, returning from another page, and a tab opened by an existing portfolio tab. An earlier session viewing no longer suppresses it. Direct fragments, reduced motion, data saving, slow connections and unavailable animation support bypass the startup cover. Interaction releases it. A four-second visible-time watchdog exposes the normal page if the document or stylesheet cannot become ready. Explicit Replay still works. Without JavaScript, the page remains its normal static document. The existing landmarks and heading remain semantic and the decorative cover does not capture pointer input. Restoring an existing document from browser history does not introduce another automatic overlay.

A follow-up first-open/reload report exposed two gaps in the first fix: loading in a hidden tab permanently bypassed the opening, and a cold main application taking more than four seconds expired its cover. The entry now starts at document readiness independently of the application's imports. It uses `readystatechange`, because `DOMContentLoaded` would still wait for the application. It waits for the stylesheet and first visibility; time spent in a hidden tab does not consume its watchdog. Main motion setup no longer owns, replaces or disposes the opening. The dedicated lifecycle handles its own page hide and history restoration.

The startup file has a different name from the removed legacy audio-opening bootstrap, which remains excluded by the existing package test. CSP, authentication, contact handling, routing and workflows are unchanged. No new asset, font, palette, dependency or animation loop was introduced.

Release verification includes first-paint traces in Chromium/WebKit with delayed or blocked scripts, a hidden tab becoming visible after more than four seconds, application arrival during an active opening, ordinary reloads and return navigation without a replay parameter, a new tab inheriting an old viewing marker, explicit replay, preferences and stylesheet-watchdog fallback, alongside existing unit, opening, browser, identity, recruiter, palette, accessibility and performance checks. Reports are local outputs; public publication is verified against the released source commit and hosted pages.

The required recruiter-access check also caught a pre-existing regression in the new phone Evidence layout. The decorative duplicate paper fan now stays on desktop, and phone guidance follows the file collection, so the first teaching file starts within the required first-screen range. Real file thumbnails, captions, filters and destinations remain available. Desktop composition is retained.
